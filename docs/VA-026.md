# VA-026 — Release versionada do VCCAprender

## Branch
`VA-026-versioned-release-build`

## Versões
- `appVersion`: versão funcional `MAJOR.MINOR.PATCH`, por defeito `0.1.0`.
- `buildNumber`: inteiro positivo usado como Android `versionCode`.
- No GitHub Actions, o número é `github.run_number`, crescente a cada execução do workflow.
- Em builds locais, passar explicitamente `-PbuildNumber=N` para não reutilizar o valor por defeito `1`.

## Nome do APK
`VCCAprender-v0.1.0-build42-release.apk` para `appVersion=0.1.0` e `buildNumber=42`.

## Pipeline
Executar **Actions → Android Release APK → Run workflow** e indicar a versão.
O workflow executa testes unitários, `assembleRelease` e disponibiliza o APK como artefacto descarregável.

## Local
```bash
./gradlew :app:assembleRelease -PappVersion=0.1.0 -PbuildNumber=42
```

## Assinatura
A release utiliza `VCCProjects.jks`, com o alias `vccprojects`. Apesar da extensão `.jks`, o ficheiro fornecido é do tipo **PKCS12**.

### Build local

Copiar `keystore.properties.example` para `keystore.properties` e preencher `storePassword`. Se a chave tiver uma password diferente, preencher também `keyPassword`; caso contrário, é usada a password do keystore. O caminho predefinido é `~/.keystores/VCCProjects.jks`.

O ficheiro `keystore.properties` e os formatos de keystore estão excluídos do Git. Nunca guardar chaves nem passwords no repositório nem passá-las como argumentos da linha de comandos.

Também são aceites variáveis de ambiente, que têm prioridade sobre o ficheiro local:

| Variável | Campo local | Valor predefinido |
|---|---|---|
| `VCC_RELEASE_STORE_FILE` | `storeFile` | `~/.keystores/VCCProjects.jks` |
| `VCC_RELEASE_STORE_PASSWORD` | `storePassword` | Obrigatório |
| `VCC_RELEASE_KEY_ALIAS` | `keyAlias` | `vccprojects` |
| `VCC_RELEASE_KEY_PASSWORD` | `keyPassword` | Password do keystore |

Os builds de release falham se o keystore ou as credenciais não estiverem disponíveis; não existe fallback para APK sem assinatura. Builds Debug não exigem estas credenciais.

### GitHub Actions

Configurar estes **repository secrets** antes de executar o workflow:

- `VCC_RELEASE_KEYSTORE_BASE64`: conteúdo binário do `VCCProjects.jks`, codificado em Base64.
- `VCC_RELEASE_STORE_PASSWORD`: password do keystore.
- `VCC_RELEASE_KEY_ALIAS`: opcional; por defeito `vccprojects`.
- `VCC_RELEASE_KEY_PASSWORD`: opcional; por defeito a password do keystore.

O workflow descodifica a chave para a diretoria temporária do runner, compila a release assinada e executa `apksigner verify --verbose` antes de disponibilizar o APK. Só o APK é incluído no artefacto.

Para verificar localmente o resultado, usar o `apksigner` dos Android SDK Build Tools:

```powershell
apksigner verify --verbose --print-certs app/build/outputs/apk/release/VCCAprender-v0.1.0-build42-release.apk
```

## Atenção
- O `run_number` aumenta por workflow, não globalmente entre todos os workflows.
- O número só aumenta no GitHub Actions; compilações locais exigem um número explícito.
- Para atualizações Android, o `versionCode` tem de ser superior ao da versão instalada.
- O workflow precisa dos secrets acima configurados no GitHub; a validação local não executa nem configura esses secrets remotamente.
